# 发布资料校验与回执恢复

适用范围：启用统一托管的官方 Python 工具和同一服务端发布链路。平台只保存固定发布快照，应用负责人查看预览后才确认收录。本说明不授权上传未经允许的源码、修改真实应用或自动确认。

## 校验与上传分开

取得门户发布规范及对应 SHA-256 的官方工具，在有当前项目上下文和执行权限的 Host 中运行。示例中的项目参数必须是本机实际应用根目录，工具放在项目之外。

```text
python <官方工具> --origin <门户根地址> --project <项目绝对路径> --dry-run
python <官方工具> --origin <门户根地址> --project <项目绝对路径> --validate
```

`--dry-run` 只做本地检查，不访问门户。`--validate` 收集同一应用包并调用 `POST /api/managed-publications/validate`，与正式上传复用服务端包校验；它不建立/轮换发布凭据或幂等键，不创建/修改 receipt，不写 binding、operation、publication、catalog，也不请求 GitLab 写操作。预检还可检查当前目录标签口径，但不代替发布归属、修订、版本、权限和最终来源核验；正式上传仍执行这些检查。

诊断以机器可读错误码和规则标识定位问题；可提供项目相对路径、行/列或字段及修正建议。诊断不回显命中内容、发布凭据、私有链接或用户绝对路径。无法安全呈现的路径/字段会省略或遮蔽。按定位修正后可重复预检；通过仅表示当前资料校验通过。

校验通过并确认分享范围后，运行同样的工具参数、去掉校验标志，才进入正式上传。更新时使用发布提示词中的 `--managed-app-id` 并保留原凭据。正式接口支持真实最小应用包；不能用它进行小包、逐文件、二分或连通性诊断，更不能把探测得到的最小快照当作完整应用源码已上传。

## 回执与不确定结果

工具在用户私有目录保存原凭据、原幂等标识、原请求及必要成功回执。Windows 使用 DPAPI，POSIX 使用私有文件权限。请保留原操作系统用户、项目目录、门户地址和 receipt；不要为绕过错误而删除、改名或重新生成身份。

```text
python <官方工具> --origin <门户根地址> --project <原项目绝对路径> --status
python <官方工具> --origin <门户根地址> --project <原项目绝对路径> --recover
```

`--status` 查看本机已保存的安全回执，不访问门户、不重新采集上传源码。`--recover` 使用原发布凭据和原幂等键，通过 `GET /api/managed-publications/receipt` 读取已有操作和已有发布回执，必要时安全更新本机回执；不重新上传源码，不在服务器创建或推进操作。回执包含私有预览能力，只交给本次负责人，不转发到公共日志、Issue 或群聊。

若原操作尚未完成，读取会明确报告待恢复阶段，不假装已生成预览。继续上传时必须沿原操作、原包与原幂等键对账；原内容发生变化时先完成或核清旧操作，再明确准备更高版本的新提交。相同幂等键对应不同正文必须拒绝，不能移动旧版本 tag。

工具已经运行并收到4xx、鉴权失败、超时或未知结果，均不属于“运行环境无法使用工具”。不要转写手工 HTTP 上传器。环境确实缺少执行权限、解释器、网络或安全存储能力时，应说明缺口并在具备条件的 Host 中继续；不能以另一条未经核验的写入路径绕过。

## 状态说明

- 校验通过：资料通过当前检查，没有上传或收录。
- `preview_ready` 且有效链接已持久化并交给负责人：预览已生成、链接已交付，仍待负责人检查确认。
- HTTP 201但没有有效链接、回执不完整或保存失败：发布结果或交接待恢复，工具必须非零退出；保留原身份及操作，用官方恢复命令处理。
- `registered`：只读查询已经确认收录；不等于应用安装、Host加载、实际调用或业务验收通过。

工具和提示词均不代负责人调用确认接口。

## 回归证据边界

本次回归用隔离 HTTP/GitLab 协议夹具、PostgreSQL 引擎和真实 CLI 子进程，检查请求/写调用计数、诊断脱敏、receipt 前后状态及未知结果恢复。ai-file-analysis 的三文件原始内容、字节数、摘要和原201响应没有保留，合成场景用于验证错误机制，不能称作原始请求逐字节回放。真实应用保持不动，实际交付和业务验收另行记录。
