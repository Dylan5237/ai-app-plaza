# 发布资料校验与回执恢复

完整资料、上传、分享及更新协议见[统一接入规范](../integration/publishing.md)。本页补充托管校验与恢复操作；直连 GitLab 的授权和请求结构不同，不复用托管包协议。

适用范围：启用统一托管的官方 Python 工具和同一服务端发布链路。平台只保存固定发布快照，应用负责人查看预览后才确认收录。本说明不授权上传未经允许的源码、修改真实应用或自动确认。

## 校验与上传分开

先读取项目与已有资料，复用已确认的作者信息、分享范围和本次上传授权；集中询问无法确认的必需项。作者中英文姓名等补齐前不运行预检，不以 `maintainers: []` 或占位资料试探服务。其余资料由 Agent 自动准备，不让作者手填文件或重复确认已有授权。

取得门户发布规范及对应 SHA-256 的官方工具，在有当前项目上下文和执行权限的 Host 中运行。示例中的项目参数必须是本机实际应用根目录，工具放在项目之外。`--origin` 保留契约中的协议、主机、端口及完整部署前缀（如 `https://plaza.example.invalid/plaza`），不截掉 `/plaza`，不追加 `/api`。

```text
python <官方工具> --origin <门户根地址> --project <项目绝对路径> --validate
```

`--validate` 已包含本地检查，再收集同一应用包并调用 `POST /api/managed-publications/validate`，与正式上传复用服务端包校验；它不建立/轮换发布凭据或幂等键，不创建/修改 receipt，不写 binding、operation、publication、catalog，也不请求 GitLab 写操作。`--dry-run` 是可选的纯本地检查，不访问门户，不能替代 `--validate`，无需强制先跑一遍。预检还可检查当前目录标签口径，但不代替发布归属、修订、版本、权限和最终来源核验；正式上传仍执行这些检查。

诊断以机器可读错误码和规则标识定位问题；可提供项目相对路径、行/列或字段及修正建议。诊断不回显命中内容、发布凭据、私有链接或用户绝对路径。无法安全呈现的路径/字段会省略或遮蔽。按定位修正后可重复预检；通过仅表示当前资料校验通过。仅预检失败时不执行 `--status` 或 `--recover`，本次没有正式提交回执可恢复。

向作者说明当前阶段、原因和下一步：资料问题依据规则与字段自动修正；门户访问/响应问题先核对完整前缀、契约、工具 SHA-256 和 HTTP 状态，可只读读取契约核实部署差异。只有 `PORTAL_REJECTED` 或没有字段诊断时，不能猜成天宫身份、版本、tag 或 Release 问题，也不要求作者反复复制完整日志。说明“服务预检未通过，尚未上传”，无法定位时交维护者核实；仅在问题修正或服务恢复后重试。完整分流见[准备与预检失败的处理](../integration/publishing.md#准备与预检失败的处理)。

校验通过并确认分享范围后，运行同样的工具参数、去掉校验标志，才进入正式上传。更新时使用发布提示词中的 `--managed-app-id` 并保留原凭据。正式接口支持真实最小应用包；不能用它进行小包、逐文件、二分或连通性诊断，更不能把探测得到的最小快照当作完整应用源码已上传。

## 广场网关返回 HTTP 500 时

用户看到 `stage: portal_response`、`httpStatus: 500` 时，保留现有项目和版本。维护人先按时间在网关错误日志中查找 `POST …/api/managed-publications/validate`。若出现 `open() … failed (13: Permission denied)` 且指向请求体临时文件，说明请求未到达广场校验服务。公开 GET 正常或小包成功都可能与这个故障同时出现。

Nginx 缓冲较大的 POST 时需要落盘。检查 worker 能否遍历每一级父目录，并在网关服务的挂载环境内用实际 worker 账户创建临时文件。若错误为 `(30: Read-only file system)`，核对 systemd 的 `ProtectSystem`、`ReadWritePaths` 和 `PrivateTmp`。即使宿主机上的目录权限正确，服务中的挂载仍可能只读。

启用 `PrivateTmp=yes` 且已验证服务内的 `/tmp` 可写时，可以给广场同源入口及提供上传的旧 API 入口配置以下路径。由 Nginx 创建缓冲目录，核验目录归 worker 所有、权限为 `0700`。

```nginx
client_body_temp_path /tmp/plaza-client-body;
```

保留原请求缓冲及大小限制。先备份当前配置，在网关服务的挂载环境中用实际运行的二进制、prefix 和候选配置执行 `nginx -t`，验证 worker 可以写入后平滑重载。发布后从用户使用的入口运行以下检查。它只向官方预检提交合成 Skill，不使用作者源码，不执行正式上传：

```bash
python scripts/check-publisher-ingress.py --origin https://portal.example.invalid/plaza
```

看到 `validated` 后，作者可以在原目录用原版本重新运行 `--validate`，通过后继续此前已授权的上传。若返回其他错误，则按新的阶段和诊断处理。

## 回执与不确定结果

只有正式提交请求已发出或工具报告已有原提交记录，才用下列命令核实原操作的失败、超时或不确定结果；正式命令仍停在本地资料检查时按诊断修正，不查回执。工具在用户私有目录保存原凭据、原幂等标识、原请求及必要成功回执。Windows 使用 DPAPI，POSIX 使用私有文件权限。请保留原操作系统用户、项目目录、完整门户地址和 receipt；不要为绕过错误而删除、改名或重新生成身份。更新使用的 `--managed-app-id` / `--expected-revision` 不传给预检或恢复命令。

```text
python <官方工具> --origin <门户根地址> --project <原项目绝对路径> --status
python <官方工具> --origin <门户根地址> --project <原项目绝对路径> --recover
```

`--status` 读取根 Manifest 定位本机已保存的安全回执，不访问门户、不重新采集上传源码，不能证明服务器实时状态。`--recover` 使用原发布凭据和原幂等键，通过 `GET /api/managed-publications/receipt` 读取已有操作和已有发布回执，并可能清除/更新本机的旧恢复信息；不重新上传源码，不在服务器创建或推进操作。“只读”指远端操作，不表示本机 receipt 字节不变。回执包含私有预览能力，只交给本次负责人，不转发到公共日志、Issue 或群聊。

若原操作尚未完成，读取会明确报告待恢复阶段，不假装已生成预览。继续上传时必须沿原操作、原包与原幂等键对账；原内容发生变化时先完成或核清旧操作，再明确准备更高版本的新提交。相同幂等键对应不同正文必须拒绝，不能移动旧版本 tag。

工具已经运行并收到4xx、鉴权失败、超时或未知结果，均不属于“运行环境无法使用工具”。不要转写手工 HTTP 上传器。环境确实缺少执行权限、解释器、网络或安全存储能力时，应说明缺口并在具备条件的 Host 中继续；不能以另一条未经核验的写入路径绕过。

## 状态说明

- 校验通过：资料通过当前检查，没有上传或收录。
- `preview_ready` 且有效链接已持久化并交给负责人：预览已生成、链接已交付，仍待负责人检查确认。
- HTTP 201但没有有效链接、回执不完整或保存失败：发布结果或交接待恢复，工具必须非零退出；保留原身份及操作，用官方恢复命令处理。
- `registered`：只读查询已经确认收录；不等于应用安装、Host加载、实际调用或业务验收通过。

工具和提示词均不代负责人调用确认接口。

截至 2026-10-19 核对的代码，`--recover` 返回并保存 `registered` 时仍可能退出 1，见[已知问题 #50](https://github.com/Dylan5237/ai-app-plaza/issues/50)。需要结合本次 JSON、保存回执及公开详情核验，分别报告收录状态与工具退出码异常，不重新上传或重复确认。`--status` 返回 0 也只表示本地查询完成，不代表已收录。完整状态/退出码解释见统一规范。

## 回归证据边界

本次回归用隔离 HTTP/GitLab 协议夹具、PostgreSQL 引擎和真实 CLI 子进程，检查请求/写调用计数、诊断脱敏、receipt 前后状态及未知结果恢复。ai-file-analysis 的三文件原始内容、字节数、摘要和原201响应没有保留，合成场景用于验证错误机制，不能称作原始请求逐字节回放。真实应用保持不动，实际交付和业务验收另行记录。
