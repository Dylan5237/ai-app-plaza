# AI应用广场需求说明

版本：0.2 · 方向已确认、环境待验证 · 2026-10-10

文档任务：[Docs #3](https://github.com/Dylan5237/ai-app-plaza/issues/3)

适用读者：产品、研发、测试及应用作者

本文记录用户于 2026-10-10 确认的产品方向和最小资料发布约定。它用于继续需求设计，不代表 Phase Freeze、Phase Accept 或相关功能已实现。公司身份源、GitLab 宿主与授权方式、Codex/WorkBuddy 的 MCP 登录与提交兼容性、性能目标和真实搜索效果仍需核验。当前原型的能力边界见[能力边界说明](capability-boundaries.md)。

## 1. 产品目标

帮助使用者从实际工作任务出发，发现并判断团队已有的 AI 应用，沿用目标系统现有的使用申请和访问入口；帮助应用作者通过自己的 Agent 整理项目资料，在明确授权后将适宜的说明资料分享给约定的内部受众。

GitLab 是项目资料和版本的来源。广场按固定提交读取经确认可分享的资料，并维护应用目录、收录记录和与广场用户关联的收藏。广场不代替 GitLab 授权项目写入，也不因收录而开放项目源码。

首期覆盖桌面网页版的应用发现、详情、使用入口及资料分享和收录；同一用户可以使用应用，也可以分享应用。广场不托管应用计算、不代替用户运行 Agent、不提供通用安装部署执行器，也不加入评论、评分、排行榜或计费。

## 2. 已确认方向

### 2.1 受众、身份与分享范围

- 首期只有一个约定的内部受众范围，不提供公开收录范围。无法确认可向该内部受众分享的项目暂不收录。
- 项目 Maintainer 或项目约定负责人确认哪些介绍和使用资料可分享。广场只展示资料清单中明确指定的内容；不会仅因文件名或仓库可读就自动公开整个 README，也不收录源码、凭据或运行环境配置。
- 读者获得已收录说明资料的权限独立于其 GitLab 源码权限。用户不需要 GitLab 账号才能成为首批广场使用者。
- 广场用户复用公司现有统一身份。实际身份提供方和接入能力待环境核验；只有首批用户全部已有 GitLab 账号且仍满足既定用户范围时，才可选择 GitLab 账号作为登录实现，不得通过缩小首批用户范围来迁就登录方式。
- 作者 Agent 的操作须受其运行 Host 的工具访问授权约束；GitLab 写入还须由作者具备目标项目所需权限并符合项目政策。广场不会代作者授予或绕过 GitLab 权限。

### 2.2 作者发布与收录

- 作者的 Agent 负责从项目上下文整理并维护 JSON 和 Markdown 资料；作者无需在广场手填结构化资料。
- 作者 Agent 在其运行 Host 已授权的工具范围内，使用具备目标 GitLab 项目相应权限的身份，并按项目政策完成所需的提交、MR 或版本准备；之后再向广场提交项目定位、固定 commit 和 manifest 路径。广场根据这些定位信息自行读取资料并生成只读预览。
- 作者查看预览后，一次确认本次分享的内部受众和具体内容，广场才收录。确认绑定预览所示的固定 commit、manifest 和资料内容；确认后若修改资料或更换 commit，须生成新预览并再次确认。
- 广场不设置逐项目的管理员审批。作者的广场确认仅授权展示预览中明确列出的分享资料，不代表授予 GitLab 写权限或批准 GitLab 侧操作。

### 2.3 版本与资料

- 每次收录必须绑定可追溯的固定 commit。存在正式版本时优先展示正式版本；Git tag 和 GitLab Release 均非强制条件。没有正式版本时如实显示为快照版本，并提供对应 commit 定位。
- 资料更新可以独立于应用软件发版。JSON 或 Markdown 更新不要求创建新的软件版本。
- 广场当前展示的软件版本切换须由责任人明确确认；普通 commit 或 webhook 不自动提升当前版本。
- 应用版本和资料快照是不同信息：资料快照 commit 用于追溯广场实际读取的内容，不自动等同于应用的软件版本。

### 2.4 发现与使用

- 以工作目标组织查找；评估搜索效果时使用真实中文任务描述，不直接承诺采用 AI 语义搜索或宣称已具备语义理解。
- 标签由作者自定义并维护。多标签筛选按同时包含处理；广场不自动改写、合并或替换作者标签。
- 继续提供两类使用入口：平台应用跳转到登记的平台链接；其他应用提供“接入我的 Agent”提示词。
- 使用申请指引或外链沿用目标系统既有流程。首期不建设广场统一审批流程；是否可访问、需何种授权及业务是否成功由目标系统决定。
- 收藏绑定广场用户身份保存，不以当前浏览器的本地状态作为唯一记录。

## 3. 用户与协作方

| 对象 | 目标与责任 |
| --- | --- |
| 使用者 | 使用公司统一身份进入广场，按任务发现应用、判断适用性，并打开目标系统或将提示词交给自己的 Agent。无需 GitLab 账号即可浏览已收录的说明资料。 |
| 作者 | 维护项目资料，审阅广场只读预览，确认本次分享的内部受众和内容。 |
| 作者的 Agent | 依项目上下文整理 JSON 和 Markdown，检查缺项，在 Agent Host 工具授权和 GitLab 项目权限都满足的条件下按项目政策准备 GitLab 内容，并提交项目、固定 commit 与 manifest 路径供广场读取。 |
| 项目 Maintainer / 约定负责人 | 确认允许向首期内部受众分享的介绍和使用资料。 |
| 使用者的 Agent | 根据接入提示词核对使用环境、取得必要授权，完成接入并说明结果。 |
| 应用广场 | 提供发现、只读预览、收录与真实状态反馈，保存广场用户收藏及必要的收录定位信息。 |
| 公司身份系统 | 为首批广场使用者提供统一身份；具体系统和接入条件待核验。 |
| GitLab | 保存应用项目、固定提交、正式版本信息及 Agent 所维护的 JSON 和 Markdown 资料。 |
| 目标应用系统 | 负责自身访问、授权、使用申请和业务处理。 |

## 4. 使用应用

### 4.1 发现与筛选

主路径：描述要完成的工作 → 浏览匹配应用 → 按作者标签缩小范围 → 查看详情 → 进入目标系统或开始 Agent 接入。

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| U01 | 按工作目标查找应用 | 用户可描述任务、输入材料或预期产出，不必预先知道项目名或技术形态。 |
| U02 | 提供可判断的目录信息 | 展示项目名称、能力说明、作者标签、作者、项目版本、创建时间和更新时间；日期语义按后续确认的口径展示。 |
| U03 | 支持标签筛选 | 支持选择、取消和清空作者标签；多个标签按同时包含处理，并可与任务查询组合。 |
| U04 | 保留通用浏览 | 未输入任务时可浏览；无结果时说明当前条件没有匹配项，并允许调整描述或筛选。无结果不表示团队中绝对不存在相应能力。 |
| U05 | 提供用户收藏 | 收藏与已登录的广场用户身份关联，不能作为应用权限或可用性证明。 |

搜索应以真实中文工作任务检验发现效果。采用关键词、语义或混合实现，以及效果阈值，待真实数据和环境验证后确定；自然语言输入本身不能证明系统理解了语义。

### 4.2 判断适用性

应用详情应说明适用任务、输入与预期产出、所需环境、使用步骤、限制、作者标签、当前应用版本、项目来源和可用入口。不得用作者未提供的信息补全事实；信息不足、来源读取异常或版本状态未确认时，应明确呈现缺口。

只有资料清单明确指定并经项目 Maintainer 或约定负责人确认的介绍和使用资料可进入分享预览。读者可通过广场查看已收录资料，不因此获得仓库源码权限。详情中应区分资料已收录、目标入口可访问和实际使用成功，不能把三者合并为一个“已可用”状态。

### 4.3 开始使用与申请

- 平台应用的“打开平台”入口指向登记的平台链接。应用自身的登录、权限申请和业务处理由该平台完成。
- 其他应用通过“接入我的 Agent”获得与所选应用版本相对应的提示词。提示词应说明来源、前置条件、所需权限、接入步骤、最小验证方式和失败处理，不得包含明文凭据。
- 点击、复制或打开入口不表示安装、接入或业务执行成功。需要访问申请时，复用目标系统已有指引或外链，广场不建立统一审批状态。
- 收藏按广场用户身份保存，浏览器切换或清理不能成为唯一的收藏记录来源。

## 5. 分享我的 AI 应用

主路径：作者让 Agent 整理项目资料并准备 GitLab 提交 → Agent 向广场提交项目、固定 commit 和 manifest 路径 → 广场读取指定资料并生成只读预览 → 作者确认内部受众和内容 → 广场收录并返回可核实的结果。

| 阶段 | 要求 |
| --- | --- |
| 整理资料 | 作者 Agent 读取项目上下文，维护 JSON 和 Markdown，识别缺项或冲突；无法从项目证据确定的信息向作者澄清，不得猜测。 |
| 准备 GitLab | 作者 Agent 在其运行 Host 的工具授权范围内，使用具备目标 GitLab 项目相应权限的身份，按项目政策完成适用的提交、MR 或版本准备。所需动作由项目流程决定；广场不执行或授权这些写入。 |
| 提交定位 | Agent 提交 GitLab 项目定位、固定 commit 和 manifest 路径。该请求不要求作者粘贴结构化数据，也不由作者在广场逐字段填写。 |
| 生成预览 | 广场读取该固定 commit 中 manifest 指向的 JSON、Markdown 及获准分享的资料，展示只读预览。读取能力、宿主 API 和授权方式须在真实环境中验证。 |
| 作者确认 | 预览展示应用资料、资料路径、固定 commit、拟分享受众和将被展示的内容。作者确认该受众和内容后，广场方可收录；确认与这份预览绑定。若作者再修改资料或更换 commit，需重新预览和确认。 |
| 收录与反馈 | 广场报告资料读取和收录结果。收录失败可单独重试，不重复上传源码；相同项目、commit 和 manifest 的重复提交不重复创建目录项。广场不得把超时、按钮点击或提示词复制推断为成功。 |

只有项目 Maintainer 或约定负责人确认过的介绍和使用资料可以列入分享范围。manifest 必须能定位这些资料；README 不因其存在而默认公开，只有被明确列入且经过确认的内容才能展示。项目无法面向唯一首期内部受众分享时，暂不收录。首期没有逐项目的广场管理员审批。

作者的确认只覆盖预览中列出的资料和首期内部受众，不扩大到源码、未列出的文件、公开受众或 GitLab 写操作。上传 GitLab 已向仓库原有读者开放内容，必须事先具有相应授权，不能由后续广场确认补授权。

## 6. 资料、版本与目录状态

### 6.1 资料来源

作者 Agent 在 GitLab 项目中维护 JSON 和 Markdown 资料。JSON 承载广场需要读取的结构化应用信息；Markdown 承载介绍、适用说明和使用指引。manifest 路径用于在固定 commit 中定位这两类资料及获准分享的说明内容。具体字段、文件命名和校验规则应在后续技术契约中确定，不能借本需求草稿宣称已经实现。

广场目录项应能追溯到 GitLab 项目、固定 commit 和 manifest 路径。GitLab 项目继续是资料与版本来源；收藏属于广场用户状态。

### 6.2 应用版本和资料更新

- 正式版本优先作为应用版本展示，但不要求项目必须使用 tag 或 GitLab Release。
- 没有正式版本时标为快照版本，关联固定 commit，不能伪装成正式发布版。
- 软件版本的当前值只能经责任人明确确认后切换。普通 commit 或 webhook 不自动改变当前版本。
- 作者可以只更新 JSON、Markdown 等资料而不发布新的软件版本。广场需区分“资料快照变化”和“应用软件版本变化”。

### 6.3 日期建议

建议将 GitLab project.created_at 标为项目创建时间，将广场当前资料快照的 activatedAt 标为更新时间，并明确标注含义；不要把同步时间标成更新时间。该字段语义和展示方式是工程建议，留待技术评审确认。

本表用于后续需求评审，不是已冻结的 Phase 验收合同。

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| A01 | 使用者没有 GitLab 账号 | 可使用公司统一身份进入广场并浏览已收录资料；实际身份提供方待环境核验。 |
| A02 | 使用者用真实中文任务查找应用并组合标签 | 按真实任务样例评估发现效果；多个标签按同时包含筛选，不承诺未经验证的语义搜索能力。 |
| A03 | 项目资料拟供首期内部受众查看 | 只预览 manifest 指定且经 Maintainer 或约定负责人确认的介绍和使用资料；README 不自动公开。 |
| A04 | 作者 Agent 发起收录 | Agent Host 工具授权和 GitLab 项目权限均满足时，按项目政策准备提交/MR/版本，再提交项目、固定 commit 和 manifest 路径；作者无需手填广场表单。 |
| A05 | 广场读取资料并生成预览 | 按固定 commit 读取并生成只读预览；作者确认受众和内容后才收录，读取失败时不宣称成功。 |
| A06 | 应用有正式版本或只有 commit 快照，或只更新了资料 | 正式版本优先；无正式版本时标为快照。资料更新不强制软件发版，commit/webhook 不自动切换当前版本。 |
| A07 | 用户收藏、打开平台、申请使用或接入 Agent 应用 | 收藏与广场用户关联；两类使用入口沿用既有流程，提示词提供来源和接入指引，入口或复制行为不表示业务已成功。 |
| A08 | 作者确认后修改资料或更换 commit | 广场基于新内容生成预览，作者再次确认后才收录。 |
| A09 | 收录失败后重试，或 Agent 重复提交相同定位 | 只重试广场收录，不重复上传源码；相同项目、commit 和 manifest 不重复创建目录项。 |

## 8. 仍待真实环境验证

以下是部署与验收前的核验项，不是重新打开本轮已确认的 D1-D3 产品方向：

- 公司统一身份系统及接入条件尚未提供，需核验其是否覆盖既定首批使用者。
- GitLab 宿主、固定 commit 读取和项目授权条件，以及 Codex/WorkBuddy 的 MCP 登录与提交兼容性仍需真实环境验证。
- 性能阈值和搜索效果需结合真实中文任务样例验证；验证前不宣称已具备 AI 语义搜索能力。
- JSON、Markdown 和 manifest 的具体字段/文件格式留待后续技术评审确定。

以上事实尚未通过真实宿主与服务验证。需求确认不能替代技术验证、Phase Freeze、Phase Accept 或业务验收。

## 9. 当前原型的证据边界

当前原型展示 17 项完整 Mock 应用资料和入口，其中 6 项为平台工作台演示、11 项为 Agent 接入提示词。项目内容、版本、日期、示例域名、工作台结果和发布反馈均不代表真实项目发布或服务集成。

本地关键词匹配、浏览器收藏、同源示例工作台和模拟发布状态只用于评审交互流程。当前没有后端服务、GitLab 集成、真实应用安装、真实 Agent 调用或 AI 语义检索。门户不会真实读取 GitLab 项目、接收外部 Agent 回传或发布资料；原型通过不能作为真实能力、Phase PASS 或业务验收的证据。
