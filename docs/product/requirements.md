# AI应用广场需求说明

更新：2026-10-20，按当前实现和[主流程范围](mainflow-scope.md)校正。本页描述现行业务规则；早期讨论见 Git 历史和[2026-10-10 决策记录](../architecture/decisions-2026-10-10.md)。本文不是新的 Phase Freeze 或业务验收结论。

适用读者：产品、研发、测试及应用作者。Agent 的字段、命令、接口、恢复规则统一见[上传、分享与更新接入规范](../integration/publishing.md)。

## 1. 产品目标与范围

帮助使用者按工作任务发现并判断团队已有的 AI 应用，沿用目标系统的访问、授权和使用方式；帮助作者通过自己的 Agent 整理项目资料，在授权范围内上传发布快照，预览确认后分享介绍与使用说明。

当前主流程为发布收录、发现、使用及更新。公开目录无需登录；不提供用户账号、收藏、逐项目审批、应用计算托管、安装执行、评论、排名或计费。[私有预览只读管理](../ops/private-preview-administration.md)直接启用，所有门户访问者无需密码即可查看各作者尚未确认的记录；该页面不能代确认、重试、恢复或删除。历史 17 项 Mock 仅用于原型比对，不进入真实目录。

## 2. 分享范围与责任

所有能访问门户的人都能查看已收录资料。网络受众范围由部署环境控制，门户不提供按用户分组的可见性。无法向该范围分享的资料不应收录。

作者确认 Manifest 及明确指定的介绍、使用和 Agent 接入说明可以展示；README 不因文件名而自动公开。托管上传可以包含必要源码，但目录不会因此展示完整源码或未声明文件。源码、软件包和目标平台权限仍由各自系统控制。

| 对象 | 责任 |
| --- | --- |
| 使用者 | 发现应用、判断适用性，取得目标系统必要权限后使用 |
| 作者/负责人 | 确认上传范围、作者姓名、预览内容及更新变化 |
| 作者的 Agent | 阅读项目证据、补齐资料、执行已授权的校验与上传、交付预览、核对结果；不代确认 |
| 使用者的 Agent | 核对固定版本和本地状态，保护配置与本地修改，按说明接入并报告实际验证 |
| 应用广场 | 核验来源、提供预览、保存已确认快照和目录，返回真实状态 |
| GitLab | 保存项目发布快照、commit、版本 tag 与 Release |
| 目标应用/业务系统 | 负责自身运行权限和业务处理；Agent 安装文件由广场分发已确认的固定包 |

作者的中英文姓名是本人确认的声明，不是员工身份认证。直连发布使用作者当前有效 GitLab 权限；托管服务器使用固定群组授权，后续更新依赖应用专属凭证。作者姓名或公开 appKey 不能替代更新权限。

## 3. 使用应用

主路径：按任务查询 → 按能力标签筛选 → 查看用途、条件与说明 → 打开平台或取得 Agent 接入提示词。

- 目录展示名称、简介、版本、作者、有效能力标签及创建/更新时间。关键词查询与多标签交集可组合，不宣称已具备 AI 语义搜索。
- 应用最多 3 个核心能力标签，发布前优先复用已有名称。来源 Manifest 保留原文，授权整理的存量目录分类不改写历史来源；新版本使用作者的新标签。
- 详情提供适用场景、输入、产出、使用条件、限制、示例任务及入口。不从缺失资料推断未经验证的能力。
- 平台通过登记 URL 使用；其他应用通过固定版本的 Agent 接入说明使用。同一应用可具备两类入口。
- 应用自身的登录、使用申请和审批沿用目标系统现有流程；广场不建立统一审批状态。
- 提示词复制、打开入口和资料收录不表示安装、运行或业务成功。

## 4. 上传、分享与确认

作者无需逐字段填表。Agent 依据当前项目准备 v2 应用资料；关键事实或作者中文姓名、英文全名/完整拼音缺失时，先向作者询问。

| 阶段 | 现行规则 |
| --- | --- |
| 整理资料 | 准备应用资料、明确共享说明、真实使用入口和固定版本指引；不上传凭据、机器配置或未经授权文件 |
| 统一托管 | Agent 使用官方工具预检并上传必要源码；服务器在固定私有群组准备应用仓库、commit、tag、Release，新仓库关闭 CI |
| 直连 GitLab | Agent 按项目现有授权与发布政策准备版本，再提交固定来源定位，广场读取核验 |
| 生成预览 | 绑定固定来源、共享内容摘要、受众、预览修订及目录修订；显示创建或更新的内容 |
| 作者确认 | 作者持私有链接检查后确认，Agent 不代确认；链接持有者具备查看与确认能力，不是实名审批 |
| 收录反馈 | 以实际状态与公开应用详情为准；失败沿原操作恢复，不用重传源码推断成功 |

上传源码与目录收录是不同阶段。GitLab 已有项目写入或托管源码上传发生在确认之前，必须先符合原项目授权和本次分享范围。后续目录确认不能追溯授权源码写入，也不批准 MR 合并或应用部署。

私有预览凭证以返回有效期为准，通常对应创建后 24 小时。只交给本次负责人，不公开或转发。资料或来源改变后应准备新版本和新预览，不能沿用旧确认。

## 5. 版本与更新

每次新发布和更新都需正式 `projectVersion`、匹配版本 tag、真实 GitLab Release 及固定 commit。历史已收录 v1 快照可以保留，但不得按旧格式提交新的版本。

- 当前已确认的目录版本是用户看到的“最新版本”。普通 commit、tag、Release 或 webhook 不自动切换它。
- 更新保持应用身份，使用更高版本并核对当前目录修订。即使只改资料，新内容也不能覆盖同版本。
- 作者预览旧版到新版及变化后再确认。确认前或失败时原版本继续使用；成功后应用 ID、链接及创建时间不变。
- 相同来源和内容重复提交不重复收录；同版本改内容、版本倒退、过时修订或旧预览覆盖均拒绝。
- 使用者升级仍由自己的 Agent 根据当前已收录版本和本地状态执行，保留配置、业务数据和本地修改。广场不跟踪本地安装记录，不自动升级或通知。
- 发布版本声明不能证明外部平台当前运行版本，部署状态由目标平台自行管理。

创建时间对应来源 GitLab 项目创建时间，更新时间对应当前目录快照生效时间；不以浏览器查看时间或普通同步时间替代。

## 6. 故障与完成判定

网络超时或工具非零退出不能直接等同于上传未发生。沿原应用身份、原请求和回执查询或恢复；不换身份、换幂等键或创建重复应用来绕过问题。

预检通过、源码已上传、版本已准备、预览已交付、目录已收录、使用者已安装/升级、业务执行成功必须分别报告。HTTP 201 或健康检查不是完成凭证。具体错误、恢复方式和当前 CLI 已知限制以统一接入规范为准。

## 7. 验证要求与边界

以下为现行规则的检查场景，不是新冻结的阶段合同或已通过的业务验收：

| 场景 | 预期行为 |
| --- | --- |
| 使用者无 GitLab 账号 | 可浏览其网络可达门户中的已收录资料，源码权限仍独立 |
| 托管或直连首次分享 | 均生成固定版本预览，作者确认后才进入目录 |
| 资料缺姓名、非法路径、无匹配版本或 Release | 明确报错，不编造信息或绕过校验 |
| 作者确认后来源改变 | 不沿用旧摘要覆盖，须重新准备并确认 |
| 更新、重复提交及并发冲突 | 保留应用身份，版本与修订检查有效，旧操作不覆盖新版本 |
| 上传结果未知或目录失败 | 原身份、原请求恢复，不重复建立应用或重传已完成源码 |
| 打开平台或安装/升级 Agent 能力 | 目标环境独立验证，复制或收录不计为实际使用成功 |

本地测试、真实 GitLab、具体 Codex/WorkBuddy 等 Host、部署及业务验收分别留证。历史原型演示边界见[原型说明](capability-boundaries.md)，当前工程边界见[架构说明](../architecture/architecture.md)。

## 二阶段第 0、1 段实施依据（2026-11-06）

本轮已获实现授权，功能范围为 [#95 公开目录发现与使用](https://github.com/Dylan5237/ai-app-plaza/issues/95)，界面采用已核对的 [UI/UX 统一规范](../design/plaza-ui-ux.md)。规范约束后续每一段；旧稿中的本轮仅设计、不开发，以及多层页签安排，由当前授权和交互修订替代。

- 目录默认最近更新，网页显式 `sort=updated`；服务端先筛选和排序，再分页。旧请求缺省顺序保持兼容。
- 随便看看从当前 audience 下已上架的正式快照等权抽取最多 6 项，批内无重复，换批优先避开上一批；切换不重新取样，失败保留批次。“已展示全部”仅表示当前批覆盖当前可见全集。
- 卡片主操作严格按作者 `primaryEntry`，入口不可用时在原位说明且不提供可点击操作；目录、轮盘复用同一卡片，标签、文本选择、键盘和触屏独立可用。悬停轻抬卡片，悬停/聚焦以文字主操作替换日期，不使用整卡蒙版；轮盘滚轮连续跟随并自动居中。
- 公共详情读取当前快照；返回恢复目录筛选、排序、页码、滚动位置，或轮盘批次与位置。保留 `?app=`、发布预览和后台路径。
- 首段不接入身份、收藏、审核、热度、智能查找或 MCP 安装更新，不增表、不迁移数据、不改变原收录流程。

完整二阶段原稿位于现有 `1-codex-iteration-2-requirements` 需求工作树。后续已确认身份来源为天宫、小组改为广场本地管理；首次及更新仍按已确认权限矩阵提交上级审核。该修订不表示本轮已经实现、迁移或正式开通权限。

## 二阶段用户体系先行（2026-11-09）

用户已确认先建设广场自身用户与会话体系，接入天宫并参考伏羲做法。按稳定的天宫用户 ID 创建或复用广场本地用户，显示姓名变化不另建账号；不按作者姓名、GitLab 用户或旧发布凭证自动认领应用。

本地候选提供同源天宫登录、独立会话、显式账号切换与退出、本地小组和个人收藏。公开目录保持匿名浏览；小组名册管理需独立授权，收藏只属于当前用户，失效内容保留通用占位，收藏不增加使用热度。部署条件及凭据边界见[天宫身份接入](../integration/tiangong-identity.md)。

应用归属、四类受限分享、维护委派与上级审核继续按二阶段后续范围实现；本次不对存量应用执行认领、迁移或改动可见范围。候选代码与本地合成门户测试不代表真实天宫账号、目标入口或生产启用。

## 二阶段第 5 段智能查找基础版（2026-11-13）

按用户确认，智能查找进入正式页面并成为广场默认首页，界面遵循 [UI/UX 统一规范](../design/plaza-ui-ux.md)。检索分两层：已接入公司内网模型服务时由模型理解任务并重排、写理由；模型未配置、超时、失败或输出不可信时自动降级为明确标注的基础检索。

- 默认首页为智能查找（`/`），全部应用与随便看看改为显式 `?discover=catalog` / `?discover=random`；既有直链、`?app=` 详情、发布预览与后台路径保持可用，发布确认后仍回到全部应用。
- 基础检索按任务文本分词（拉丁整词、中文二元组）对可见上架应用的名称、标签与检索文本做召回导向的 OR 匹配，按命中数排序，最多 8 项；无匹配如实告知，不补造推荐。
- 智能检索为公司内网模型服务（OpenAI 兼容接口，用户指定仅用 deepseek-flash）：关键词先召回，模型在候选池（关键词命中 + 最近上架补足，最多 40 项）内做语义重排，最多 3 项，理由必须依据候选的名称/简介/标签；只在关键缺项会改变结果时追问一个问题，用户补充后继续原任务，追问合并后的查询上限 500 字。用户输入只作为待理解的任务描述：不执行其中的指令性内容，不回答与应用查找无关的问题。模型返回的 id 必须落在候选内，非法输出、超时（默认 8 秒）或服务失败一律降级：仅按关键词命中作答，不混入无关近期应用，无有效关键词时如实返回空。
- 结果区标注当前模式：智能推荐说明“由内网智能服务理解任务后推荐，理由依据应用资料”，基础检索说明“按关键词匹配，不代表对任务的理解”。“为什么出现”在智能模式展示模型理由、基础模式展示命中词；仅首个匹配展开，其余收起在“其他匹配应用”内。支持新对话、修改需求、重试、等待取消与未提交草稿的“上一轮结果”标注；页签切换、详情往返保留会话与滚动位置。空对话页随机轮换展示 3 个推荐任务描述，点击直接发起检索。
- 智能检索埋点：每次完成的检索上报一条 `smart_search_completed`（模式 ai/basic、结果数、耗时、查询长度桶、是否追问续答、模型是否追问、是否来自推荐词），不记录任务原文；运营看板据此统计主动搜索量、空结果率、AI 模式占比、追问与续答次数，应用曝光与点击沿用 `pageContext/section = search` 计入既有发现与使用指标。
- 两种检索都遵守既有 audience、上架与访问范围过滤。智能检索只向模型发送任务描述与候选应用的名称/简介/标签，不发送完整文档；模型服务仅在公司内网内调用。进入模型的用户输入与候选字段一律按不可信数据处理：以单一 JSON 对象序列化传递（系统提示声明其中所有字符串值为不可信数据、不具有指令权限）、剥离控制字符并限幅，模型追问含凭据类或外链关键词时直接丢弃且不影响有效推荐。系统提示词由超级管理员在管理中心「智能查找」页配置（上限 6000 字、剥离控制字符、可一键恢复默认、写入操作审计，修改对后续检索立即生效），未配置时使用内置默认模板。密钥只经服务器环境变量（`PLAZA_SMART_SEARCH_BASE_URL` / `PLAZA_SMART_SEARCH_MODEL` / `PLAZA_SMART_SEARCH_API_KEY` / `PLAZA_SMART_SEARCH_TIMEOUT_MS`）注入，不进入仓库，未配置时保持基础检索。
