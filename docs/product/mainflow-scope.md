# 首版主流程与边界

依据：用户于 2026-10-10 确认“先把发布收录、发现和使用这条主流程跑通”，并随后明确“先不做用户登录模块，就单纯一个所有人都能用的门户”。开发合同见 [Phase #7](https://github.com/Dylan5237/ai-app-plaza/issues/7)。这一最新指令覆盖架构提案中首期登录、账号绑定和用户收藏的安排。

## 本次实现

1. 作者复制发布提示词，让自己的 Agent 从项目中整理应用资料，按原有授权准备 GitLab 固定提交。
2. Agent 提交数字项目 ID、固定 commit、appKey 和 manifest 路径；广场通过作者已有 GitLab 授权独立读取指定资料。
3. 作者打开本次专属链接，预览将展示的内容后确认收录。收录失败时保留本次状态，恢复核验和收录，不重传源码。
4. 所有能访问门户的人都能搜索应用、组合作者标签、看详情，再打开平台链接或复制固定版本的 Agent 接入提示词。

平台不执行 GitLab 写入，不下载或运行应用，不因收录开放源码、软件包或目标平台权限。不做登录、账号、收藏、管理审批、托管、排行榜或移动端；本阶段不增加周期同步或高级检索。

## 无登录时的发布边界

目录与已收录说明对部署地址的访问者开放。公司内网或其他网络访问范围由部署环境控制，门户不提供按用户分组的可见性。

发布接口使用作者 Agent 的既有 GitLab 授权，核验有效 Maintainer/Owner 权限；预览与确认需要本次短期专属凭证。**持有完整链接的人可以查看并确认本次发布**，因此不应转发；这不是实名审批，也不能声称区分了真人和自动化。MCP 不提供确认工具，发布提示词要求由作者查看并确认。

GitLab 令牌仅通过请求头提供，服务端临时加密保存用于确认时再次核验，收录完成后清除。发布记录 24 小时后失效，运行中的服务每分钟清理过期令牌，启动时也会清理；停机期间不执行清理。临时发布凭证与 GitLab 令牌不同；它不能读取其他候选，也不能读取任意仓库文件。服务端只读取 manifest 声明的共享资料。

## 验证口径

本地自动化使用明确标注的 GitLab 协议测试服务和 PostgreSQL 引擎，验证真实服务逻辑、持久化、网页与 MCP 进程。测试服务不会被运行配置自动启用，也不会给正式目录预置 17 项 Mock。

真实 GitLab 读权限、项目资料收录、具体 AI Host 接入和部署验收分别报告；本地通过不代替这些结果。历史交互原型在 `?prototype=1` 保留用于比对，其模拟状态不进入新目录。
